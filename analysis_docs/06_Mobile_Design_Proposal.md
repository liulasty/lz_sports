# LZ Sports 移动端架构与设计方案

## 1. 现状分析与可行性评估
在对 `lz_sports` 项目最新 `master` 分支代码进行分析后，当前系统架构对扩展移动端具备极高的**天然优势**与**解耦性**：

### 1.1 后端接口的天然适配
- **无状态架构**：后端（`lz_sports_backend`）采用纯 RESTful API 设计，安全层使用无状态的 JWT Token（由 `JwtAuthenticationFilter` 校验）。移动端只需在 HTTP 请求头中携带 Token 即可完成鉴权，无需考虑 Session 共享或 Cookie 跨域问题。
- **CORS 友好**：`SecurityConfig.java` 中已配置了允许所有 Origin (`*`) 的 CORS，这意味着无论是本地调试 H5，还是部署在任意域名的移动端应用，都不会遇到跨域阻碍。
- **业务解耦**：现有的 `/api/auth`, `/api/event`, `/api/registration`, `/api/score` 接口设计粒度适中，可直接被移动端复用。

### 1.2 前端现状的局限性
- 当前的 `lz_sports_frontend` 强依赖于 **Element Plus**。尽管可以通过媒体查询（Media Queries）强行做成响应式，但 Element Plus 本质上是桌面端 UI 框架，在移动端上的交互体验（如弹窗、日期选择器、表格下拉）并不理想，且包体积较大。

**结论**：强烈建议**不要**在原有桌面端项目中强行适配移动端，而是**新建一个独立的移动端工程 (`lz_sports_mobile`)**。

---

## 2. 移动端技术选型建议

针对校园运动会这一特定场景（用户通常使用手机微信或校园 App 访问），推荐以下技术栈组合：

### 方案 A：跨平台方案（强烈推荐）
基于 **Uni-app (Vue 3 + Vite)** + **uv-ui / uni-ui**
- **优势**：一次开发，可同时编译出 **H5 网页版** 和 **微信小程序版**。在校园场景下，微信小程序能极大降低用户的参与门槛（扫码即用、即用即走），并且可以利用微信的扫码 API 方便裁判在现场进行运动员检录。
- **复用性**：能够完美复用现有的 Vue 3 Composition API 和 Pinia 状态管理经验。

### 方案 B：纯 H5 方案
基于 **Vue 3 + Vite** + **Vant 4** (有赞的移动端 Vue 组件库)
- **优势**：学习成本极低，完全延续桌面端的开发习惯，只需将 UI 库从 Element Plus 替换为 Vant 4，通过 Nginx 部署在特定的子域名（如 `m.lzsports.com`）。

## 3. 移动端功能模块设计

移动端的受众主要分为两类：**普通学生/运动员** 和 **现场裁判/赛事管理员**。

### 3.1 运动员端 (C端 - 核心功能)
1. **门户首页 (Home)**
   - 轮播图（对接后端的 `sportsimg` 表）
   - 近期赛事预告与快捷报名入口。
2. **赛事与报名 (Event & Registration)**
   - 赛事详情展示（时间、介绍、项目列表）。
   - **移动端专属优化**：在报名表单中采用移动端友好的级联选择器（Picker）选择院系/专业/班级（读取 `department` 宽表）。
3. **我的中心 (My Profile)**
   - 运动员认证申请（H5 拍照上传证件/学生证）。
   - 报名记录跟踪状态（审核中/通过/拒绝）。
   - 个人成绩查询与证书展示。
4. **消息通知 (Notifications)**
   - 移动端友好的消息列表，接收审核结果与成绩发布的站内信。

### 3.2 现场裁判端 (B端 - 拓展功能)
1. **移动成绩录入**
   - 替代原有的 Excel 导入，裁判可以在田径场现场，通过手机快速录入（`ScoreController.upsert`）具体项目的成绩。
2. **现场检录 (可选)**
   - 结合小程序的扫码能力，扫描运动员的报名二维码进行赛前检录。

## 4. 前端工程架构设计图

如果新建 `lz_sports_mobile` 工程，建议的目录结构如下：

```text
lz_sports_mobile/
├─ src/
│  ├─ api/             # 完全复用桌面端的 API 定义（axios/uni.request）
│  ├─ components/      # 移动端基础组件（卡片、列表项、空状态）
│  ├─ pages/           # 页面视图（小程序规范一般叫 pages）
│  │  ├─ index/        # 首页
│  │  ├─ event/        # 赛事详情与报名
│  │  ├─ score/        # 成绩查询
│  │  └─ user/         # 个人中心
│  ├─ stores/          # Pinia 状态管理（userStore 存储 Token）
│  ├─ utils/           # request.js (封装统一拦截器与错误处理)
│  ├─ App.vue
│  └─ main.js
├─ package.json
└─ vite.config.js
```

## 5. 对后端接口的少量改造建议
虽然现有接口基本可以直接使用，但为了极致的移动端体验，后端可以考虑做以下微调：
1. **增加分页简化版接口**：移动端通常采用“下拉刷新、触底加载”的瀑布流交互，现有的 `PageResult` 完全支持，但可以提供一些字段更少的 `LiteVO`，减少移动端的网络流量。
2. **微信生态接入 (若做小程序)**：后端可在 `AuthController` 中新增 `/api/auth/wx-login` 接口，对接微信的 `code2Session`，实现一键静默登录，免去学生手动输入账号密码的繁琐。
