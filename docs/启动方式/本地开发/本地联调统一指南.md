# 本地联调统一指南（Windows，无 Docker）

本文档用于统一前后端本地联调步骤，默认前提：

- 本地 MySQL 已配置开机自启动。
- 本地 Redis 安装目录为 `D:\develop\redis\windows-64\redis-2.8.9`，启动脚本为 `start.bat`。
- 前端通过 Vite 代理访问后端：`/api -> http://localhost:8080`。

## 1. 一次性环境准备

### 后端
- JDK 17+
- Maven 3.6+
- MySQL（本地可连接）
- Redis（本地可连接）

### 前端
- Node.js 18+
- npm

## 2. 启动顺序（统一）

建议严格按以下顺序执行，减少端口与依赖问题：

1. 启动 Redis（如未随系统启动）
2. 确认 MySQL 正常可连
3. 启动后端（8080）
4. 启动前端（5173）
5. 访问页面并联调接口

### 2.1 启动 Redis

在 PowerShell 执行：

```powershell
cd D:\develop\redis\windows-64\redis-2.8.9
.\start.bat
```

如 Redis 已在运行，可跳过。

### 2.2 启动后端

在项目根目录执行：

```powershell
cd lz_sports_backend
mvn spring-boot:run
```

或在 IDEA 中运行 `com.lz.BackendApplication`。

### 2.3 启动前端

在新终端执行：

```powershell
cd lz_sports_frontend
npm install
npm run dev
```

默认访问地址：`http://localhost:5173`

## 3. 联调验收清单

满足以下检查项即可认为“本地联调可用”：

- 前端页面可正常打开，且无白屏。
- 调用登录、报名、成绩查询等接口时，前端请求路径为 `/api/...`。
- 后端控制台能看到对应请求日志，返回非 5xx。
- 浏览器开发者工具中请求实际转发到 `http://localhost:8080`。

## 4. 常见故障排查

### 4.1 前端报网络错误或 404
- 确认后端已启动在 `8080`。
- 确认前端请求是 `/api/...`，不是写死到错误地址。
- 检查 `vite.config.js` 是否仍保留 `/api` 代理。

### 4.2 后端启动失败（数据库连接）
- 检查 MySQL 服务是否启动。
- 检查数据库账号、密码、库名与本地配置一致。
- 若端口不是默认 `3306`，同步调整后端配置。

### 4.3 后端启动失败（Redis 连接）
- 检查 `D:\develop\redis\windows-64\redis-2.8.9\start.bat` 是否已执行。
- 检查 Redis 端口和密码是否与后端配置一致。

### 4.4 前端端口冲突
- 使用其他端口启动前端，例如：

```powershell
npm run dev -- --port 5174
```

### 4.5 CORS/代理异常
- 本地开发应优先走 Vite 代理，不建议前端直接跨域请求后端。
- 修改代理后需重启前端开发服务器。

## 5. 建议的本地调试方式

- 后端：IDEA Debug 模式运行，便于断点排查业务逻辑。
- 前端：`npm run dev` 热更新调样式与交互。
- 数据问题优先通过后端日志 + 数据库实际记录联合定位。
