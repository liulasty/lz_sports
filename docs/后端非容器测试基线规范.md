# 后端非容器测试基线执行与扩展规范

本文档用于统一后端在**不使用 Docker/Testcontainers**前提下的测试执行方式，保障本地调试与 CI 可稳定运行。

## 1. 适用范围

- 仅适用于 `lz_sports_backend` 的非容器测试基线。
- 目标是提供“持续可跑、可回归、可扩展”的最小质量门禁。

## 2. 基线执行步骤

在项目根目录执行：

```bash
cd lz_sports_backend
mvn -Pnon-container-baseline test
```

预期结果：

- Surefire 执行通过
- 无 `Failures` / `Errors`
- 输出 `BUILD SUCCESS`

## 3. 当前基线内容

当前 profile `non-container-baseline` 固定包含以下测试：

- `RegistrationServiceImplTest`
- `ScoreServiceImplTest`

说明：以上测试均为可 mock 的服务层边界测试，不依赖容器环境。

## 4. 常见故障排查

### 4.1 运行失败但提示 BaseMapper 为 null
- 现象：测试调用 `updateById`、`save` 等 MyBatis-Plus 方法时报空指针。
- 处理：在测试中使用 spy + stub（如 `doReturn(true).when(service).updateById(...)`），避免走真实持久层。

### 4.2 profile 未生效
- 现象：执行了大量不在基线内的测试。
- 处理：确认命令为 `mvn -Pnon-container-baseline test`，且 `pom.xml` 内 profile 的 surefire includes 正确。

### 4.3 新增测试后 CI 失败
- 现象：本地可跑，CI 报依赖环境异常。
- 处理：检查新测试是否引入了真实数据库、Redis、外部网络或容器依赖；基线测试应全部可 mock。

## 5. 扩展规范（新增测试纳入基线）

新增测试要纳入非容器基线，需满足：

1. **无容器依赖**：不可依赖 Testcontainers、Docker 网络环境。
2. **可重复执行**：不依赖本机临时状态或顺序执行。
3. **边界优先**：优先覆盖异常分支、权限分支、空输入分支。
4. **可维护**：测试命名体现业务意图，断言聚焦单一行为。

纳入步骤：

1. 在 `src/test/java` 增加或扩展服务层测试类。
2. 确保测试通过 mock/stub 隔离基础设施依赖。
3. 更新 `pom.xml` 的 `non-container-baseline` includes（如新增类需要纳入）。
4. 本地执行 `mvn -Pnon-container-baseline test` 验证通过。
5. 确认 `.github/workflows/ci.yml` 与 `.github/workflows/backend-smoke-ci.yml` 无需额外改动（默认调用该 profile）。

## 6. 与迭代流程关系

- 该基线用于支撑 backlog 中非容器路线任务（如 `BE-002`、`BE-004`）。
- 若后续要恢复容器/集成测试，应新增独立任务，不直接污染当前基线。
